# Matpris – project memory

Swedish grocery price comparison. Search a product, see one merged list of prices from nearby chains, a map of the stores (Apple MapKit JS), and "Cheapest near you". README.md has the full technical description; this file records decisions, constraints and preferences from earlier sessions so they aren't re-litigated.

## Owner preferences
- UI language: **English** (product and store names stay as the chains publish them, i.e. Swedish). Numbers via `src/lib/format.ts` (`19.40 kr`, `1.1 km`).
- Stack: **SvelteKit 3 + TypeScript**, package manager **Bun** (`bun install`, `bun run dev|test|check|build`). Svelte 5 runes.
- Map: **Apple MapKit JS** (not Leaflet). Must fit all stores on screen; map is big (full-height right column on desktop, ~65vh on mobile).
- The owner tests from **Lund** (55.7047, 13.1910); use it for location-based checks.
- Work is pushed directly to `main` on `felixgoff/matpris` (private).
- Claude Code plugins **Impeccable** (design: `/impeccable critique|polish|audit…`) and **Ponytail** (`/ponytail`, `/ponytail-review`) are enabled in `.claude/settings.json`. They load only at session start.

## Running and secrets
- `PUBLIC_MAPKIT_TOKEN` (MapKit JS JWT) is read from the environment at startup (declared in `src/env.ts`, used in `src/lib/mapkit.ts`). Locally it lives in `.env` (gitignored). In cloud sessions it must be set as an environment variable in the environment settings. **Never commit the token.** The current token expires **2026-11-06** and has no origin restriction (MapKit warns in the console). Follow-up idea: sign short-lived tokens server-side from the `.p8` key (Team ID `JWR5UX55S5`, Key ID `W6JH93XCAZ`).
- Without a token the app still works; the map shows "The map could not be loaded".
- **Desktop app** (Electrobun 2.0.5, macOS, 2026-10-30): `bun run desktop` / `bun run desktop:build`. SvelteKit uses `adapter-node`; `electrobun.config.ts` copies `build/` into the app as `Resources/app/server`, and `desktop/main.ts` (Bun main process, `mainProcess: "bun"`; the experimental "cottontail" runtime doesn't promise Node APIs) serves its `handler` on a free `127.0.0.1` port and opens a `BrowserWindow` on it. Electrobun's own output goes to `desktop/build` / `desktop/artifacts`, never `build/` (SvelteKit's). The MapKit token is built in from `.env` via `define` (the config reads `.env` relative to itself; Hutch doesn't run it from the project folder), so rebuild after renewing it. WebKit's geolocation works through Electrobun's permission dialog. ICA shows "busy" in the app because its session lives in `scripts/` outside the bundle.
- **Desktop releases and self-update** (2026-10-30, modelled on RustRadar): the version is `package.json`'s only (`electrobun.config.ts` reads it; `bun run bump patch` = `npm version --no-git-tag-version`). `.github/workflows/desktop-release.yml` builds on `macos-26` (Xcode 26+ for the `.icon`) and publishes release `v<version>` with the zipped app, `stable-macos-arm64-update.json` and `stable-macos-arm64-Matpris.app.tar.zst`, but only when that version isn't released yet (private repo: macOS minutes count 10×, and main gets many pushes); `bump.yml` bumps, pushes and starts the release (a push with `GITHUB_TOKEN` doesn't trigger workflows). Repo secret `PUBLIC_MAPKIT_TOKEN` feeds the build. `desktop/update.ts` uses Electrobun's `Updater` (`release.baseUrl` = `…/releases/latest/download`, `generatePatch: false`): it installs a newer release before the window opens (progress window, 8 s check timeout, failures open the installed version), checks hourly while open, and the page's `UpdateToast` offers Restart via `/__desktop/update[/restart]` (routes the main process serves ahead of SvelteKit; the toast only polls when `window.__electrobunWebviewId` exists). The repo is **private**, decided by the owner: the updater's plain `fetch` of `baseUrl` files is answered through the GitHub API with `gh auth token` from `/opt/homebrew/bin/gh` (kept in memory; asset → 302 to signed storage, followed without the token). No gh login means no updates, never a failed launch. Don't bake a token into the app or publish releases publicly without asking.

## Data sources and hard constraints (do not work around)
- **Willys, Hemköp** (Axfood): public JSON `https://www.<site>/search?q=…&size=40`, stores at `/axfood/rest/store?online=false`, prebuilt into `data/{willys,hemkop}-stores.json` (`bun run stores:axfood`, one request per site) so the one turn per 10 s goes to searches only. One national online price (no unauthenticated store selection), so `pricing: 'chain'`. robots.txt: `Crawl-delay: 10` (enforced per host in `src/lib/server/http.ts`) and `Visit-time: 0400-0845` UTC (not enforced; documented in README). Searches are `latestOnly`: a newer search takes over a queued turn (the old one fails as superseded), so a wait is at most one Crawl-delay instead of stacking.
- **City Gross**: site JSON `https://www.citygross.se/api/v1/Loop54/search?SearchQuery=…&type=product&Take=40` and `/api/v1/PageData/stores` (38 stores). Default-store prices, so `pricing: 'chain'`. robots.txt disallows the `/loop54/` page route only; requests spaced 2 s. Each product has a category path, used by relevance. Members-only offers are skipped.
- **Lidl**: `https://www.lidl.se/q/api/search?...` (returns 401 if `accept: application/json` is sent, so we send `*/*`). Only food categories `Food`/`F+V`. An item on a Lidl Plus offer has no plain `price`; its non-member price is `regionsPrices[<default region>].currentLidlPlusPrice.price.oldPrice` (the struck-through figure on lidl.se), and its unit price is worked out from the size because the listed kr/l is the member's. Member prices themselves are skipped. Store list is prebuilt in `src/lib/server/data/lidl-stores.json` from Lidl's store sitemap (`bun run stores:lidl`, ~4 min, 1 req/s).
- **ICA**: live server-side search when a WAF session cookie file exists (decisive discovery 2026-10-29 via the human-journey recorder `scripts/ica-record.mjs`, which logs the shop's own API traffic). The search journey `GET /stores/{id}/api/webproductpagews/v6/product-pages/search?...q=` responds 200 with full product JSON to plain `fetch` **when an `aws-waf-token` cookie rides along** — the earlier "cookies do not carry server-side / CAPTCHA on search" recon results were artifacts of the burned IP reputation from heavy probing, not permanent walls. The token lives a few minutes; `bun run warm:ica` (`scripts/ica-warm.mjs`) mints a fresh one by opening the shop in the persistent Chrome profile `scripts/.ica-profile/` and saving cookies to `.ica-profile/session.json`; it exits <10 s when the IP is clean (headless is fine). `src/lib/server/chains/ica.ts` reads that file, re-runs the warm script when stale (max once a minute, 120 s timeout) and on an HTTP 202 challenge, then retries; if the WAF still challenges, the search returns `throttled` — never solve the visual puzzle programmatically (only a human in `HEADED=1 bun run warm:ica` clears it, as designed). Prices anchor to Maxi ICA Stormarknad Gunnesbo, Lund (store `1088004`), presented as chain pricing like Lidl's. Lexicon: `PER_LITRE_WITHOUT_DEPOSIT`/`PER_1KG`/`EACH` → `l`/`kg`/`st`; `promoPrice` < regular `price` maps to current price with `oldPrice` (incl. `promoUnitPrice` as the deal's comparison price). Store list `data/ica-stores.json` (356 stores, `bun run stores:ica`). Backup plan if warm/live ever breaks: the prebuilt catalogue crawl (`scripts/ica-catalogue.mjs`, resumable, leaf-first, safes every other page) and the Lidl-style index adapter — no longer the primary path.
- **Coop** (2026-10-29): coop.se prints its APIM subscription keys in its own page config (`personalizationApiSubscriptionKey`, `storeApiSubscriptionKey`); `src/lib/server/chains/coop.ts` reads them like the site's apps do and caches them for a day. Search: `POST external.api.coop.se/personalization/search/global?api-version=v2&store=251300&groups=CUSTOMER_PRIVATE&device=desktop&direct=false` with `{query, resultsOptions:{take:40}}`. Stores: `GET proxy.api.coop.se/external/store/stores/map?conceptIds=12,6,95&invertFilter=true&api-version=v2` (720 with the site's own concept filter). PDP URL `https://www.coop.se/handla/varor/{name-slug}-{id}` works without a category slug. Prices are one national list (like Axfood), `pricing: 'chain'`. Deals: `onlinePromotions` — `MULTI_BUY_FIXED_PRICE` bundle `priceData.b2cPrice` ÷ `numberOfProductRequired` becomes `deal` ({quantity, each, total}); other fixed promotions become `price` + `oldPrice`; mapping fixtures live in `coop.test.ts`. MedMera member prices (`medMeraRequired`) are skipped, like City Gross. 2 s between Coop API calls.
- ICA's un-priced fallback is gone: with an online adapter, its stores come from `data/ica-stores.json` (the OSM/Nominatim path in `stores/osm.ts` is retired as an ICA source).
- The matval repo (Colin-Andrew-Rasiga/matval) was the reference: its Coop spider derives from the same personalization API + page-source key. Its ICA spider's session-refresh pattern (small Playwright run keeps re-minting the WAF token; plain scrapy reads server-side with the cookies) is what the live ICA data path follows — its Oct-2025 log shows 33k requests this way with zero blocks.
- Logos in `static/logos/` are from the chains' own sites, except ICA's (Wikimedia Commons, because ica.se blocks us). Coop's is its pinned-tab SVG coloured `#00aa46`, with the viewBox cropped.

## Key behaviours (and why)
- **Auto search radius** (`stores/radius.ts`): start 1.5 km, ×1.6 until ≥12 stores from ≥3 priced chains, cap 30 km; if empty, stretch to the nearest store. Max 5 stores per chain, 25 total. Radius is sized by priced chains only; map-only stores are added inside the same circle afterwards. The shopper can also pick a size with − / + on the map's chip (0.5–30 km steps, `radius` param on `/api/search` and `/api/stores`, "Auto" goes back): a picked circle holds every store inside it (no 5-per-chain cap, up to 150), which costs no extra requests because every chain prices nationally.
- **Share** (the "Cheapest near you" heading): `html-to-image` draws an off-screen copy of the answer label (room for its steel strip, no shadow) at 2×, then the share sheet, else the clipboard, else a download. Product photos in the copy go through `/api/image`, which fetches only the chains' image hosts, because City Gross's image server doesn't allow cross-site drawing; a photo that won't load becomes the grey no-photo tile.
- **Search stream** (`server/search.ts`, `/api/search`): NDJSON. The `area` event with priced stores first, then a `chain` event per chain, then a second, complete `area` event with the remaining map-only chains plus `no-online-prices` chain events. Prices cached 15 min.
- **Relevance** (`normalize.ts` `relevance`): whole word or compound head (+ Swedish endings both ways: "banan"↔"bananer", "mjölken") is a match; a word that merely starts with the query is `weak` ("Fantasty" for "fanta"). Matches are `best` when the product is the thing searched for (including a brand search: every searched word is a whole word of the product's brand, so "fanta" keeps "Orange Fanta Läsk", whose type word "läsk" would otherwise make it a mention), `mention` when the query only flavours another product type or baby food (hand-kept PRODUCT_TYPES list, or City Gross's category). Only the top tier present is ranked and can be "Cheapest near you"; the rest fold into "other products". Products sold by weight carry `perKg` and, from average weight, `approxEach`.
- **Multi-buy deals** (`axfood.ts` `toHit`): Axfood `potentialPromotions[0]` with `qualifyingCount > 1` becomes `deal {quantity, each, total, unitPrice, mixAndMatch, plusDeposit, limit}`; single-item promotions become `price` + `oldPrice` ("Sale"). The UI toggle "Count multi-buy deals" (default on) makes sorting and "Cheapest near you" use the deal price and say "each when you buy N".
- **Location**: MapKit `showsUserLocation` (needs the `user-location` library) moves the search to the device on first fix. Entering an address stops following the device; "Use my location" resumes. Default is Lund.
- **Map pins**: custom logo pins, with tiered `DisplayPriority` so MapKit thins collisions instead of letting the wide cheapest label pile onto its neighbours: the cheapest store is `Required`, other priced stores `High`, and the default-location pin 900 (above stores, below the cheapest). Hidden pins reappear as you zoom in. The view fits the search circle with pin-sized padding (fitting the pins themselves zooms out too far). `animate: false`, because overlapping animated fits ended at the wrong zoom. Un-priced-chain pins are faded (`online: false`); priority and fading follow `CHAINS[].online`, so a chain gaining prices needs no map change.

## Verifying changes
- `bun run check`, `bun run test` (vitest: normalize, radius, Axfood and Coop mapping), `bun run build`.
- Browser check: run `bun run dev`, then a Playwright script (Chromium is preinstalled; `require('playwright')`) with a context that grants geolocation set to Lund. Search "fanta" or "kaffe" and check the chips, the Cheapest card, the deal text, that all `.store-pin` elements are inside `.map`'s bounds, that there is no horizontal scroll at 390px, and that there are no page errors. Look at screenshots, not just DOM counts.
- Don't hammer the chains: Axfood allows 1 uncached request per 10 s per host.
