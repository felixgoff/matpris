# Matpris – project memory

Swedish grocery price comparison. Search a product, see one merged list of prices from nearby chains, a map of the stores (Apple MapKit JS), and "Cheapest near you". README.md has the full technical description; this file records decisions, constraints and preferences from earlier sessions so they aren't re-litigated.

## Owner preferences
- UI language: **English** (product and store names stay as the chains publish them, i.e. Swedish). Numbers via `src/lib/format.ts` (`19.40 kr`, `1.1 km`).
- Stack: **Tauri 2** app (macOS, Windows, Linux, Android, iOS) with a **Rust backend** (`core/`, crate matpris-core) and a **SvelteKit 3 + TypeScript** page (adapter-static SPA, Svelte 5 runes). Package manager **Bun** (`bun run dev|app|android|test|check|build`). Decided 2026-11-09 ("switch everything from Electrobun to Tauri for proper phone support"; backend in Rust, not TS in the webview).
- Map: **Apple MapKit JS** (not Leaflet). Must fit all stores on screen; map is big (full-height right column on desktop, ~65vh on mobile).
- The owner tests from **Lund** (55.7047, 13.1910); use it for location-based checks.
- Work is pushed directly to `main` on `felixgoff/matpris` (private).
- Claude Code plugins **Impeccable** (design: `/impeccable critique|polish|audit…`) and **Ponytail** (`/ponytail`, `/ponytail-review`) are enabled in `.claude/settings.json`. They load only at session start.

## Running and secrets
- `PUBLIC_MAPKIT_TOKEN` (MapKit JS JWT) is declared in `src/env.ts` as **public + static**: built into the page (the apps have no server), so a renewed token needs a rebuild. Locally in `.env` (gitignored); repo secret `PUBLIC_MAPKIT_TOKEN` for releases. **Never commit the token.** The current token expires **2026-11-06** and has no origin restriction. Follow-up idea: short-lived tokens signed from the `.p8` key (Team ID `JWR5UX55S5`, Key ID `W6JH93XCAZ`). Without a token the app still works; the map shows "The map could not be loaded".
- **Layout** (2026-11-09): `core/` the backend (adapters, `http.rs` per-host spacing, `cache.rs`, `normalize.rs`, `stores/`, `search.rs` streams `SearchEvent`s to an mpsc sender, `geocode.rs`, `image.rs`); store lists in `core/data/*.json` (`include_str!`). `src-tauri/` the app: commands `search` (Channel; a newer search aborts the old), `cancel_search`, `stores`, `geocode`, `image` (data: URL), `update_status`/`update_restart`; windows are created in Rust (`main`), an `ExitRequested` guard + exit when `main` is destroyed. `server/` = axum dev server with the old `/api/*` routes; `bun run dev` runs it + vite (proxy `/api` → 127.0.0.1:8787), so browser checks still work. `src/lib/api.ts` picks invoke vs HTTP (`'__TAURI_INTERNALS__' in window`). The port was checked line by line against the old TS by reviewer agents (JS truthiness, Number() parsing, Lidl region order, etc.); the TS source is in git history before `efc6830`.
- **ICA cookie jar** (`chains::ica::CookieJar`, set at startup): desktop app = hidden webview window + `cookies_for_url`, accepting only a *fresh* `aws-waf-token` (WebKit persists an old one the WAF already rejected); if no token in 20 s the window is **shown** for the person (3 min). Phones = `plugins/ica-session` (Kotlin offscreen WebView + CookieManager, which expires the old token first; Swift WKWebView), shown in a dialog/sheet for a person if challenged. Dev server = `scripts/ica-warm.mjs` via `server/src/ica_jar.rs`. Never solve the challenge in code.
- **Desktop self-update** (`src-tauri/src/update.rs`, behaviour as the Electrobun app had): tauri-plugin-updater, registered only when `TAURI_UPDATER_PUBKEY` was set at build (`option_env!`; CI also merges `plugins.updater.pubkey` into the config, else plugin init panics). Private repo: the endpoint is the latest release's `latest.json` **API asset URL**, fetched with `gh auth token` (Homebrew, /usr/bin, GitHub CLI Windows paths) + `Accept: application/octet-stream`; `latest.json`'s URLs are API asset URLs too (written by the publish job after upload); the token is dropped on the redirect to signed storage. Before the window opens: check (8 s), progress window `static/updating.html`, install, restart; hourly while open; the page's `UpdateToast` offers Restart. No pubkey/no gh = never updates, never a failed launch. Don't bake a token into the app or publish releases publicly without asking.
- **Releases** (`.github/workflows/desktop-release.yml`, name "Release"; `bump.yml` starts it by filename): version from `package.json` only (`bun run bump patch`), builds only when `v<version>` isn't released (private repo; macOS minutes 10×). Desktop matrix macos-26 / windows-latest / ubuntu-22.04 (`bunx tauri build`), android job (Tauri APK aarch64 + Wear APK, same key), iOS compile check (continue-on-error, no signing), publish uploads installers, `.sig`s, APKs and then `latest.json`. Secrets: `PUBLIC_MAPKIT_TOKEN`, `TAURI_SIGNING_PRIVATE_KEY[_PASSWORD]`, `ANDROID_KEYSTORE` (base64) + `_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`; variable `TAURI_UPDATER_PUBKEY`. Not yet set up by the owner as of 2026-11-09; the workflow has never run with Tauri. Old Electrobun installs don't update to the Tauri app.

## Data sources and hard constraints (do not work around)
- **Willys, Hemköp** (Axfood): public JSON `https://www.<site>/search?q=…&size=40`, stores at `/axfood/rest/store?online=false`, prebuilt into `core/data/{willys,hemkop}-stores.json` (`bun run stores:axfood`, one request per site) so the one turn per 10 s goes to searches only. One national online price (no unauthenticated store selection), so `pricing: 'chain'`. robots.txt: `Crawl-delay: 10` (enforced per host in `core/src/http.rs`) and `Visit-time: 0400-0845` UTC (not enforced; documented in README). Searches are `latestOnly`: a newer search takes over a queued turn (the old one fails as superseded), so a wait is at most one Crawl-delay instead of stacking.
- **City Gross**: site JSON `https://www.citygross.se/api/v1/Loop54/search?SearchQuery=…&type=product&Take=40` and `/api/v1/PageData/stores` (38 stores). Default-store prices, so `pricing: 'chain'`. robots.txt disallows the `/loop54/` page route only; requests spaced 2 s. Each product has a category path, used by relevance. Members-only offers are skipped.
- **Lidl**: `https://www.lidl.se/q/api/search?...` (returns 401 if `accept: application/json` is sent, so we send `*/*`). Only food categories `Food`/`F+V`. An item on a Lidl Plus offer has no plain `price`; its non-member price is `regionsPrices[<default region>].currentLidlPlusPrice.price.oldPrice` (the struck-through figure on lidl.se), and its unit price is worked out from the size because the listed kr/l is the member's. Member prices themselves are skipped. Store list is prebuilt in `core/data/lidl-stores.json` from Lidl's store sitemap (`bun run stores:lidl`, ~4 min, 1 req/s).
- **ICA**: live server-side search when a WAF session cookie file exists (decisive discovery 2026-10-29 via the human-journey recorder `scripts/ica-record.mjs`, which logs the shop's own API traffic). The search journey `GET /stores/{id}/api/webproductpagews/v6/product-pages/search?...q=` responds 200 with full product JSON to plain `fetch` **when an `aws-waf-token` cookie rides along** — the earlier "cookies do not carry server-side / CAPTCHA on search" recon results were artifacts of the burned IP reputation from heavy probing, not permanent walls. The token lives a few minutes; `bun run warm:ica` (`scripts/ica-warm.mjs`) mints a fresh one by opening the shop in the persistent Chrome profile `scripts/.ica-profile/` and saving cookies to `.ica-profile/session.json`; it exits <10 s when the IP is clean (headless is fine). `core/src/chains/ica.rs` asks its CookieJar for a fresh session when stale (max once a minute) and on an HTTP 202 challenge, then retries; if the WAF still challenges, the search returns `throttled` — never solve the visual puzzle programmatically (only a human in `HEADED=1 bun run warm:ica` clears it, as designed). Prices anchor to Maxi ICA Stormarknad Gunnesbo, Lund (store `1088004`), presented as chain pricing like Lidl's. Lexicon: `PER_LITRE_WITHOUT_DEPOSIT`/`PER_1KG`/`EACH` → `l`/`kg`/`st`; `promoPrice` < regular `price` maps to current price with `oldPrice` (incl. `promoUnitPrice` as the deal's comparison price). Store list `core/data/ica-stores.json` (356 stores, `bun run stores:ica`). Backup plan if warm/live ever breaks: the prebuilt catalogue crawl (`scripts/ica-catalogue.mjs`, resumable, leaf-first, safes every other page) and the Lidl-style index adapter — no longer the primary path.
- **Coop** (2026-10-29): coop.se prints its APIM subscription keys in its own page config (`personalizationApiSubscriptionKey`, `storeApiSubscriptionKey`); `core/src/chains/coop.rs` reads them like the site's apps do and caches them for a day. Search: `POST external.api.coop.se/personalization/search/global?api-version=v2&store=251300&groups=CUSTOMER_PRIVATE&device=desktop&direct=false` with `{query, resultsOptions:{take:40}}`. Stores: `GET proxy.api.coop.se/external/store/stores/map?conceptIds=12,6,95&invertFilter=true&api-version=v2` (720 with the site's own concept filter). PDP URL `https://www.coop.se/handla/varor/{name-slug}-{id}` works without a category slug. Prices are one national list (like Axfood), `pricing: 'chain'`. Deals: `onlinePromotions` — `MULTI_BUY_FIXED_PRICE` bundle `priceData.b2cPrice` ÷ `numberOfProductRequired` becomes `deal` ({quantity, each, total}); other fixed promotions become `price` + `oldPrice`; mapping fixtures live in `coop.rs`'s tests. MedMera member prices (`medMeraRequired`) are skipped, like City Gross. 2 s between Coop API calls.
- ICA's un-priced fallback is gone: with an online adapter, its stores come from `core/data/ica-stores.json` (the OSM/Nominatim store lookup was retired and not ported; `stores::registry::with_map_only_stores` is a no-op while every chain is online).
- The matval repo (Colin-Andrew-Rasiga/matval) was the reference: its Coop spider derives from the same personalization API + page-source key. Its ICA spider's session-refresh pattern (small Playwright run keeps re-minting the WAF token; plain scrapy reads server-side with the cookies) is what the live ICA data path follows — its Oct-2025 log shows 33k requests this way with zero blocks.
- Logos in `static/logos/` are from the chains' own sites, except ICA's (Wikimedia Commons, because ica.se blocks us). Coop's is its pinned-tab SVG coloured `#00aa46`, with the viewBox cropped.

## Key behaviours (and why)
- **Auto search radius** (`stores/radius.ts`): start 1.5 km, ×1.6 until ≥12 stores from ≥3 priced chains, cap 30 km; if empty, stretch to the nearest store. Max 5 stores per chain, 25 total. Radius is sized by priced chains only; map-only stores are added inside the same circle afterwards. The shopper can also pick a size with − / + on the map's chip (0.5–30 km steps, `radius` param on `/api/search` and `/api/stores`, "Auto" goes back): a picked circle holds every store inside it (no 5-per-chain cap, up to 150), which costs no extra requests because every chain prices nationally.
- **Share** (the "Cheapest near you" heading): `html-to-image` draws an off-screen copy of the answer label (room for its steel strip, no shadow) at 2×, then the share sheet, else the clipboard, else a download. Product photos in the copy go through the backend (`image` command → data: URL in the app, `/api/image` in a browser), which fetches only the chains' image hosts, because City Gross's image server doesn't allow cross-site drawing; a photo that won't load becomes the grey no-photo tile.
- **Search stream** (`core/src/search.rs`; Tauri `search` channel / `/api/search` NDJSON): NDJSON. The `area` event with priced stores first, then a `chain` event per chain, then a second, complete `area` event with the remaining map-only chains plus `no-online-prices` chain events. Prices cached 15 min.
- **Relevance** (`core/src/normalize.rs` `relevance`): whole word or compound head (+ Swedish endings both ways: "banan"↔"bananer", "mjölken") is a match; a word that merely starts with the query is `weak` ("Fantasty" for "fanta"). Matches are `best` when the product is the thing searched for (including a brand search: every searched word is a whole word of the product's brand, so "fanta" keeps "Orange Fanta Läsk", whose type word "läsk" would otherwise make it a mention), `mention` when the query only flavours another product type or baby food (hand-kept PRODUCT_TYPES list, or City Gross's category). Only the top tier present is ranked and can be "Cheapest near you"; the rest fold into "other products". Products sold by weight carry `perKg` and, from average weight, `approxEach`.
- **Multi-buy deals** (`core/src/chains/axfood.rs` `to_hit`): Axfood `potentialPromotions[0]` with `qualifyingCount > 1` becomes `deal {quantity, each, total, unitPrice, mixAndMatch, plusDeposit, limit}`; single-item promotions become `price` + `oldPrice` ("Sale"). The UI toggle "Count multi-buy deals" (default on) makes sorting and "Cheapest near you" use the deal price and say "each when you buy N".
- **Location**: MapKit `showsUserLocation` (needs the `user-location` library) moves the search to the device on first fix. Entering an address stops following the device; "Use my location" resumes. Default is Lund.
- **Map pins**: custom logo pins, culled by `cull()` in `StoreMap.svelte` (MapKit's `displayPriority`/`collisionMode` left them piled up, verified 2026-10-30): placed most important first (the cheapest and the store hovered in the list always show, then the location pin, priced stores, map-only stores, nearest first), and a pin that would overlap one already placed gets the `culled` class (`visibility: hidden`; MapKit's `visible` only applies on its next redraw). MapKit's blue dot reserves its spot. Re-culled on `region-change-end`, so hidden pins reappear as you zoom in. The view fits the search circle with pin-sized padding (fitting the pins themselves zooms out too far). `animate: false`, because overlapping animated fits ended at the wrong zoom. Un-priced-chain pins are faded (`online: false`); priority and fading follow `CHAINS[].online`, so a chain gaining prices needs no map change.

## Verifying changes
- `bun run check`, `bun run test` (= `cargo test --workspace --exclude matpris`: normalize, radius, http spacing, cache, every chain's mapping), `cargo clippy --workspace --all-targets` (keep it at zero warnings), `bun run build`; `cargo test -p matpris` for the app crate (watch bridge); `cd wear && ./gradlew testDebugUnitTest`.
- Browser check: run `bun run dev` (Rust dev server + vite), then a Playwright script (Chromium is preinstalled; `require('playwright')`) with a context that grants geolocation set to Lund. Search "fanta" or "kaffe" and check the chips, the Cheapest card, the deal text, that all `.store-pin` elements are inside `.map`'s bounds, that there is no horizontal scroll at 390px, and that there are no page errors. Look at screenshots, not just DOM counts.
- Don't hammer the chains: Axfood allows 1 uncached request per 10 s per host.
